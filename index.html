02 / Engineering notes

How I approach problems.

Not just a technology list — concrete implementation choices and honest next steps.

01 / Backend design

Task API: small surface, clear contracts

Built: FastAPI routes with Pydantic validation, UUID identifiers, explicit 404 responses, and health checks.

Tradeoff: In-memory persistence simplifies the first iteration but does not survive restarts.

Next: Postgres persistence, automated tests, and authorization.

Review code ↗
02 / Security workflow

Security alerts: from noise to triage

Built: A client-side lab with synthetic events, severity/status filtering, contextual investigation notes, and CSV export.

Boundaries: No live telemetry or remote collection. Imported data stays in the browser.

Next: Add test fixtures, structured normalization, and rule tuning.

Run the lab ↗
03 / Product iteration

FORGE: turning routines into software

Built: A standalone training application that grew across several iterations, with exercise logging and fitness progress interfaces.

Tradeoff: Local browser storage is useful for prototyping, but is not a synchronized account backend.

Next: Account-based synchronization, accessibility review, and user testing.

04 / About the builder

Real-world constraints build better engineers.

My interest in engineering spans software, systems, and cyber defense. I build tools that solve practical problems, then look for the weak points — input validation, failure handling, data integrity, and whether a user can actually complete the task.

Military logistics experience gives me a useful perspective on inventory, traceability, disciplined processes, and operational reliability. I'm developing that experience further through software engineering study, projects, and security labs.

What I'm building

Web applications, Python utilities, backend services, and practical security analysis interfaces.

How I learn

Read the documentation, build the smallest useful version, test real behaviors, and refine the weakest parts.

What I'm aiming for

Software engineering, backend development, security engineering, and defensive security roles.

Working principles

Clear documentation, reproducible demos, accurate project claims, and respectful security testing in authorized environments.
